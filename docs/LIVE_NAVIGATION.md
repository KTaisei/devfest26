# 前景GPS・音声案内とGemini判断補助

2026-11-10追加。すべて訓練・試験表示です。Google Mapsアプリと同等の品質・バックグラウンド常駐・実災害向けの利用を保証しません。ARは追加していません。

## 操作

1. `/home` の操作パネルか `/profile` で「GPSの自動取得・同意設定」を一度有効にします。GPS・外部サービス送信、Gemini、支援検索を別々に選べます。目的地選択後、「徒歩の道順を表示」を押します。支援の承諾後は `/support` または `/helper` で「自分の現在地から合流地点への道順」を押します。
2. 保存済みのGPS・Google送信同意を使い、「GPS・音声案内を開始」を押します。専用の全画面地図で現在地を追従し、次の曲がり角・残り距離・時間目安・GPS精度を表示します。
3. 音声はブラウザのSpeechSynthesisです。提供元やオンライン利用は端末・ブラウザの音声エンジンに依存します。音声に個人名や他人の座標を含めません。「消音」「もう一度案内」「案内を終了」を使えます。非対応時は画面案内を使います。
4. 経路外の有効GPSが3回続いた場合は、開始時の送信同意に基づき本人の現在地から同じ目的地へ再計算します。最低30秒間隔で、同時の重複要求を防ぎます。失敗時は経路外の注意を維持し、架空道路には切り替えません。
5. GPS watchはアプリ全体で1つです。画面遷移中も続き、タブ背景化で停止、戻ると自動再開します。音声案内は背景化・別画面への移動で終了し、音声の再開だけ開始操作が必要です。画面ロック中やOSに停止された後の取得・案内は提供しません。
6. 目的地付近を推定して案内を終了します。これは入口の確認や対面合流の証明ではありません。合流は従来どおり、双方の目視確認と別操作が必要です。

## 一度の同意と自動GPS（2026-11-10更新）

- `services/locationConsent.ts` はバージョン付きの3つの同意フラグのみlocalStorageへ保存します。座標・移動履歴・識別情報・トークンは保存しません。ブラウザ／端末ごとの設定で、別端末・サイトデータ削除時は再設定します。保存失敗はその起動中だけ有効として画面に通知します。
- `LocationSession` がアプリ全体のwatchを所有し、`services/foregroundLocation.ts` が前景復帰・遅延したネイティブwatchの解放・無効値の拒否・10秒での失効を管理します。Ionicで画面がキャッシュされてもwatchは増えません。実座標は `useLocationSession` のメモリだけです。
- 地図の現在地は各GPS更新を反映し、地域情報の照会地点は移動250mごとに更新します。初回・背景からの復帰時も更新します。経路は計算開始時点の出発地を固定し、GPS更新だけで結果を消したり自動で再計算したりしません。経路外での再計算は案内側の制限に従います。
- プロフィールまたは各画面の同意設定で撤回できます。GPS／サービス利用の撤回時はwatchを解放し、取得位置を破棄、位置を使う操作を停止します。別タブでの設定変更も反映します。すでに送信した通信は取り消せません。Gemini同意の撤回は今後の操作へ反映され、依頼時にサーバーへ保存済みの同意を撤回するには受付中の支援を中止します。
- OS・ブラウザの位置権限は別管理です。アプリから「永久に許可」を強制できません。拒否時はエラーとサイト設定の案内を表示し、再試行ボタンは権限を修正した後の復旧用です。通常の取得・画面復帰にボタンは不要です。
- プロフィールの位置共有は自動で有効にしません。依頼・承諾・目視での合流確認も自動化しません。Geminiへ正確な座標を送る必要はなく、既存の匿名の数値／状況だけを使用します。APIの各操作の同意検証は維持します。

## GPS進行判定

- 全体の実道路形状へ投影した距離を使い、単純な直線距離だけで曲がり角や到着を判定しません。
- 精度35m超、10秒超古い位置、未来2秒超の位置は進行させず、案内を保留します。10秒更新がない場合も保留します。
- 前進範囲を時間と精度で制限し、経路が近くで交差しても遠い区間へ飛ばないようにします。後退方向のGPS揺れでは進行を戻しません。曲がり角を8m通過してから次区間へ進めます。
- 目安50m・15m以内で次の案内を読み上げます。同じ区間・段階の繰り返しを抑えます。
- 経路残り20m以内かつ終点から20m以内の有効位置が2回続いた場合だけ、目的地付近と推定します。GPS停止や精度低下時は連続回数をリセットします。
- 建物内・高架下・並行道路・折返し・短い区間での実用精度、発話のタイミング、各OSの停止条件は屋外実機で未検証です。これは独自の試験用進行処理で、Google Navigation SDKではありません。

## 支援情報の自動取得

プロフィールで位置共有・支援受付・対応能力を設定します。保存済みのGPS・支援検索の同意があり、新しいGPSを取得できている場合、協力者の周辺依頼は5秒、本人の依頼・承諾・合流確認状態は3秒ごとに自動取得します。ページの再読み込み操作は不要です。ネットワーク通信自体が不要という意味ではありません。

一時的な保存競合が続く場合は再試行可能なエラーを表示します。既存の一覧を取得中も残し、初回取得・失敗・条件に合う依頼なしを区別します。GPSが10秒以上更新されない場合、同意撤回、画面遷移、受付無効で周辺検索を止めます。GPS復旧時は保存済み同意で再開します。本人が依頼した受付中の支援だけ、支援画面の表示中に30秒間隔で位置を更新し、元の期限は延長しません。相手の正確な位置は取得しません。

## Geminiが担当すること

**合流候補比較**：依頼時と承諾時に双方が保存済みのGemini同意を有効にしている場合だけ使用します。両者の2km圏内の公開候補を近い順に最大3件取り、各自30分以内の通常徒歩経路が確認できたものだけを比較します。AIに渡すのは候補順と匿名化した「合計秒数・長い方の秒数」だけです。座標・住所・施設名・個人の所要時間・利用者ID・個人設定は送りません。AIは候補indexだけを返し、バランスを優先して選択します。最短合計より120秒超長い候補は採用しません。安全性や入口の確認は行いません。

**避難状況の整理**：`/home` の操作パネルを開き「Geminiで状況を整理する」から、本人が観測した揺れ・通行障害を申告します。保存済みのGemini同意に基づき、地域の地震情報の取得状態・件数と本人の支援状態を合わせ、次に確認する行動を提案します。情報不明を安全と見なしたり、本人の申告から救助対象を推測したりしません。確認行動の候補はサーバーのルールで限定します。

いずれもAIの自由生成文・座標・経路をそのまま使いません。構造化結果を検証し、未設定・停止・タイムアウト・候補外回答・余分な出力・不完全な出力は固定ルールに戻します。UIはGeminiとルールによる提案を区別します。既存の `GEMINI_BACKEND=vertex` 設定とADCを使えます。AI Studioキーへの自動切替はありません。

## 検証

Mac・Windows共通：`npm run test:navigation`、`npm run test:backend`、`npm run build`。前回のAPI契約変更時は `npm run api:export`、`npm run api:types` を実行します。CIの両OSでも進行判定と同意・GPSライフサイクルのテストを実行します。今回の同意保存はフロントのみの変更で、API契約は変更していません。

ローカルの純粋関数テストは曲がり角、GPS揺れ、古い位置、精度不良、経路外、位置の飛び、折返し近くでの誤到着を確認します。サーバーは匿名入力、候補外出力の拒否、同意、既存の承諾競合・位置の非公開を確認します。実機での連続GPS・音声・マイク不要の音声出力、合流フロー全体、実Vertexでの新しい構造化出力の検証状況は [TESTING.md](TESTING.md) に記録します。
