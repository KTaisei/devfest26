# アーキテクチャ

## データの流れ

```text
Ionic React UI
  ├─ Zustand: 言語、選択中の出発点、プロフィール
  ├─ TanStack Query: APIデータ、状態の再取得
  ├─ Firebase Auth: 匿名サインイン（設定した場合）
  └─ Axios + Bearer Token
       ↓ /api/v1
FastAPI
  ├─ Pydantic: 入出力契約と検証
  ├─ Auth: デモセッションまたはFirebase ID Token検証
  ├─ RouteOptimizer: NetworkXグラフによる候補探索
  ├─ MatchingEngine: 候補評価、同意、状態遷移、競合制御
  ├─ GeminiService: サーバー所有の固定災害情報のみ翻訳
  └─ Repository
       ├─ MemoryStore: ローカル用・RLock・例外時ロールバック
       └─ FirestoreStore: Admin SDK・トランザクション
```

## 経路探索

模擬グラフのノードから100m以内の出発点だけを受け付けます。最寄りノードへスナップし、そのノードから避難先までの候補を計算します。GPS地点からノードまでの道路は検証できないため、線を生成せず、距離・時間にも含めず、注意書きを表示します。

閉塞・未確認・高リスク道路は除外します。車いすでは階段・非対応道路・勾配5%超を除外します。規制道路は距離重みを2倍にします。時間は重み付き距離÷歩行速度の模擬推定です。災害種別に対応しない避難先は対象外です。到着先自体が出発点の場合は0m候補です。経路がなければ `no_route` を返します。

模擬画面ではGoogle Mapsは背景地図だけを担当し、経路は架空グラフで計算します。キー未設定ではSVG模式図を表示します。別の `/navigation` 画面ではサーバー側のGoogle Routes APIで実道路の通常徒歩経路を取得し、データ種別を `real_preview` とします。実GPSの画面状態・経路は模擬支援へ流用しません。[実データ対応](REAL_DATA.md)に出所・同意・未検証事項をまとめています。

## マッチング

必要能力・言語（通訳時）・共有同意・30分以内の位置・到達可能性を満たす支援者だけを候補にします。支援者の到着が10分以内で、合流後に両者の移動制約を満たす避難先があり、支援者自身の最短避難に対する追加時間が10分以内であることを確認します。これらはデモの閾値で、実災害向けに検証された値ではありません。

依頼の確認・送信を依頼者の同意、承諾操作を支援者の同意として扱います。候補は最短到着の1名へオファーし、支援者の承諾で確定します。Firestoreでは依頼、支援者claim、依頼者claimをトランザクションで更新します。承諾時に位置・道路・プロフィールを再検証し、オファーの承諾期限は作成から5分で、期限ちょうどから承諾を拒否します。未承諾オファーは `expired` にし、依頼を `waiting` に戻します。依頼者claimは保持し、同じ依頼で別の候補を手動探索できます。期限切れの相手は同じ依頼の再探索から除外し、候補を使い切ったら空配列を返します。自動で次の相手へ送信する処理は未実装です。承諾が成立すると、双方の移動制約で到達できるノードから合流地点を決定してマッチに保存し、両者へ共有します（詳細は下記）。地点は公開ノードのみで、当事者の正確な現在地をレスポンスに追加しません。辞退・取消後は新規要請が可能です。

```text
waiting → offered → accepted → meeting → assisting → completed
             └→ rejected
offered → expired（match） / waiting（元の依頼）
waiting / offered / accepted / meeting / assisting → cancelled
```

期限切れ処理は本人の依頼・マッチ取得、候補探索、状態変更の前と、60秒ごとの保守処理で行います。画面は3秒ごとのポーリングで期限切れと再探索ボタンを反映します。更新直前にトランザクションで再検証するため、先に承諾・取消が成立した状態は上書きしません。旧データも `createdAt` から期限を計算し、マイグレーションなしで失効します。

## 模擬合流地点と初回案内

承諾トランザクション内で、双方がそれぞれの移動制約で10分以内に到達できる公開ノードを評価します。両者の制約を組み合わせた合流後の避難経路、災害種別、支援者の追加時間10分以内も確認します。最小の合計移動時間から60秒以内の候補では、災害・移動条件に合う架空の避難場所を優先します。有効な地点がなければ409で承諾を拒否し、支援者claimを作りません。これは模擬評価ルールであり、実際の安全性を示しません。

`meetingPoint` は承諾前と旧レコードではnullです。承諾後は両参加者に同じ地点を返し、第三者にはマッチ自体を公開しません。完了後も地点を保持します。承諾時の道路条件のスナップショットで、自動再計算・経路案内はありません。条件変更時は中止・再依頼が必要です。

`/` からの初回アクセスだけ案内へ誘導します。`services/onboarding.ts` は案内済みフラグのみlocalStorageへ保存し、保存できなければ次回も案内します。位置・認証情報は保存しません。直接の画面URLは維持し、スマートフォンでも上部の案内リンクを利用できます。

## 保存とプライバシー

- users：本人の設定。API経由でのみ書き込む。
- private_locations：正確な位置。フロントから直接読めない。
- support_requests：位置を含まない支援依頼。
- matches：参加者IDと状態・推定時間・承諾後の模擬合流地点。参加者の正確な現在地は含まない。
- helper_claims / request_claims：二重確定と多重依頼を防ぐサーバー専用ドキュメント。
- road_status：管理者による模擬道路変更。

位置は更新から30分で利用不可になります。稼働中のAPIは60秒ごとに期限切れ位置を削除し、Firestoreでは `expiresAt` のTTLも設定します。TTL削除は非同期です。共有無効時は位置を削除します。進行中の支援がある場合は先に取消・完了が必要です。プロフィール変更も進行中の支援がある間は拒否します。Firestore Admin SDKはルールを迂回するため、API内の認証・所有者検証とIAMが必須です。

ローカルデモセッションはメモリに保持し、再起動・再読込で復元しません。実在個人のデータを保存しないでください。Firestoreを設定してもデモセッションはプロセス内なので、クラウドで複数インスタンス運用する際はFirebase認証を使用します。

## 現段階の限界

データ走査は小規模デモ向けの全件scanです。利用者数の増加前に、地域・状態でのクエリとインデックス、共有レート制限、監査ログ、オファーキュー、全件走査を避ける期限クエリとジョブを追加します。支援・災害シナリオは模擬専用で、実道路案内・地震公開情報の試験画面とは独立しています。従来シミュレーションには実情報を流用しません。通常画面のP2P接続は下記を参照してください。実災害向けの経路安全性判定・通知やバックグラウンド常駐はありません。

## Geminiの接続境界

`GEMINI_BACKEND` でdeveloper / vertexを明示選択します。Vertexは独立した `GEMINI_PROJECT_ID` と `GEMINI_LOCATION` を指定しADCで認証します。Firebaseのプロジェクトを暗黙に流用せず、AI Studioキーも渡しません。失敗時は定型文だけに切り替え、別の課金経路へ再送しません。API契約のproviderは従来どおりgemini / template / template_fallbackで、接続方式に依存しません。モデル・接続設定を変更したらAPIを再起動します。

## 実位置フロー（通常画面）

通常の `/home` は全画面の実地図です。初期位置は未取得で、同意後の実GPSだけを使用し、架空のZustand位置を読みません。旧ホームは `/simulation` です。通常の `/support`・`/helper` は実位置用に分離した `AssistancePage` を使用します。

P2Pの551/556は `local_earthquakes.py` が現在地の地震細分区域で絞ります。参照データは `data/reference` のJMA/GSI一次資料です。国土地理院の `skhb04` から実在する地震対応指定緊急避難場所を取得し、通常徒歩経路はGoogle Routesへ接続します。安全性・被災・開設は推測しません。

実位置支援は `real_assistance` / `real_private_locations` / `real_assistance_claims` を使います。外部サービスによる公開合流地点の選定と両者の実道路確認後に、Firestoreトランザクションで二重承諾を防ぎます。レスポンスには相手のGPS・経路・利用者IDを含めません。合流地点は双方に共通の公開座標で、道順は本人の現在地から個別計算します。双方の目視・新しいGPSによる確認後だけ `met` とします。

状態は `waiting → accepted → met → completed`。途中から `cancelled` / 30分で `expired` に遷移できます。中止・完了・期限切れ時に非公開位置とclaimを削除します。プロフィール変更は進行中の実位置支援でも拒否します。全件scanの制限、出典・同意・データ更新の責務は [REAL_DATA.md](REAL_DATA.md) を参照してください。
