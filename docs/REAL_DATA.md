# 実データ対応の段階と開発境界

2026年11月10日、ユーザーによるスマートフォン動作と合流の確認後、実データ対応へ進みました。優先対象はWeb版、緊急地震速報の配信サービスは未契約です。

## 今回追加した機能

ホームの「実道路の案内（試験）」から `/navigation` を開きます。通常のGoogle徒歩経路を表示する試験画面です。避難先を推薦・判定する機能ではありません。模擬支援の画面は従来の架空道路を使用します。両画面に訓練表示を残し、データの出所を区別します。

1. 地図をタップして出発地・目的地を指定する。座標入力も利用可能。
2. GPSを使う場合は「同意して現在地を取得」を押す。読み取りとGoogleの地図上への表示はその操作時だけで、常時追跡しない。地図表示のためGoogleへ位置を送信することをボタン前に明記する。
3. プロフィールを保存し、選んだ2地点をTASUKUとGoogleに送信することへ同意する。
4. 「徒歩経路を表示」で実道路の線・手順・距離・移動時間を確認する。
5. 各手順のリンクからGoogleストリートビューを開く。画像は過去の撮影で、現況やARではない。撮影範囲によっては画像が存在しない。

APIは本人の保存済みプロフィールを読み、通常歩行1.0m/s、その他0.7m/sとして距離から時間を概算し、Googleの所要時間以上の値を表示します。個別の速度測定や利用者が指定する速度は未実装です。**Googleの通常徒歩経路では階段・勾配・幅員・車いす対応を検証していません。条件に対応した経路として表示しません。** 階段回避等を選んだ場合は、その希望を確認できないことも明記します。今後は実測・公的データで通行条件を確認した道路グラフを導入し、不明な区間を対応済みと推測しない設計にします。

GPSと経路の出発地・目的地はこの画面のメモリにだけ保持し、模擬支援用Zustand状態・Firestore・localStorageへ保存しません。画面からの経路リクエストはPOST本文で送り、座標をURLやログに追加しません。Googleへの送信は利用者の明示操作時だけです。APIエラーに上流の座標・資格情報を含めず、外部接続失敗時に架空の経路へ置き換えません。出発地・目的地・プロフィールが変わると、以前の結果を非表示にします。

## 合流経路

承諾済みで進行中のマッチに「合流地点までの模擬経路を表示」を追加しました。`POST /matches/{id}/route` は参加者だけに、本人が指定した模擬出発点から公開の架空合流地点までの経路を返します。相手の私有位置は読まず、レスポンスにも含めません。現在の道路状態と本人の移動条件で再計算し、通行経路が失われた場合は409です。承諾前・終了後は409、第三者は404です。

**実際の合流地点への案内は未実装です。** 現在の合流地点を実在する待合場所として扱わないでください。実支援の導入時は、実在施設の公開位置・入口・開設状態・災害種別との適合・双方の移動条件を確認し、模擬支援とはデータ・APIを分けて導入します。匿名認証には本人確認がないため、実支援での本人確認・迷惑行為対策も別途設計します。

## 地震情報と緊急地震速報

`GET /earthquakes/recent` は気象庁の公開Atom長期フィードから地震関係の見出し最大5件と発表時刻・原文リンクを取得します。サーバーで5分間キャッシュし、各ブラウザは1分ごとに状態を取得します。長期フィード自体の更新間隔もあるため、即時性を保証しません。取得時刻と発表時刻を分け、取得失敗はunavailable、フィード内の該当なしは空リストで示します。停止・遅延を「地震なし」と表現しません。

これは**緊急地震速報ではありません**。`eewStatus=not_connected` を常に明示し、警報音・予想震度・到達秒数の生成や自動避難経路変更を行いません。気象庁の公開情報をAIで安全判定しません。

緊急地震速報の次の実装には、対象サービスとWebアプリ利用者への再配信条件の確認が必要です。契約後にサーバー側の常時受信プロセスを設け、報番号・更新・取消・訓練報の区別、切断検知、再接続、発表時刻と受信時刻、地域の対応、重複排除を実装します。現在の最小0インスタンスのCloud Run APIに、常時受信が保証されると仮定しません。認証情報はSecret Manager等で保持し、ブラウザに配布しません。

公式資料： [気象庁の入手方法](https://www.jma.go.jp/jma/kishou/know/jishin/eew/katsuyou/receive.html)、[公開XMLの留意事項](https://xml.kishou.go.jp/xmlpull.html)、[DMDATA.JPのEEW説明・再配信条件](https://dmdata.jp/docs/eew/)。契約の申込みや有料契約は今回行っていません。

## Street ViewとAR

今回のWeb版は[Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)によるストリートビュー確認です。カメラ映像への矢印表示やARナビゲーションは未実装です。ARは[ARCore Geospatial](https://developers.google.com/ar/develop/geospatial)等の位置合わせ・VPS・端末対応・権限・精度評価が必要で、Street View画像の表示だけでは成立しません。まずWebの地図・文字の道順を確認し、その後に対象OSを決めてネイティブ構成を検証します。

## 開発・設定

`backend/.env.cloud` に以下を設定し、APIを再起動します。初期デモでは既定で無効です。

```dotenv
REAL_ROUTES_ENABLED=true
ROUTES_PROJECT_ID=tasuku-77c63
```

Google CloudでRoutes APIを有効化し、実行アカウントに `roles/serviceusage.serviceUsageConsumer` を付与します。サーバー側ADCで呼び出し、ブラウザ地図キーを経路APIへ流用しません。[GoogleのOAuth設定](https://developers.google.com/maps/documentation/routes/get-api-key)に従っています。Routes APIも課金対象になり得ます。既存のハッカソンクレジットの適用は別途請求画面で確認します。

外部接続は `services/real_routes.py`、公開情報は `services/earthquakes.py`、模擬合流経路は `services/meeting_routes.py`、UIは `NavigationPage.tsx` と共通地図に分離しています。経路APIは同一プロセスで利用者ごと10回/分までに制限します。匿名アカウントの大量作成や複数インスタンスにまたがる制限は未対応のため、一般公開サービスに拡大する前にApp Check・共有レート制限・監視を整備します。
