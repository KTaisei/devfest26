# 実位置・地震・支援フロー（2026-11-10）

通常の `/home` は実データの試験画面です。初期の現在地は空で、GPS取得への同意前に位置を読みません。架空の福山駅位置へのフォールバックはありません。旧グラフの訓練画面は `/simulation`、旧支援は `/simulation-support`・`/simulation-helper`・`/simulation-matching` に分離しました。

## 利用者の操作

1. 公開版の `/profile` で言語・移動条件を保存します。支援を使う場合は位置共有を、支援者は受付状態と対応能力も設定します。
2. `/home` の「同意して現在地取得」を押し、端末の位置情報を許可します。地図は画面全体に表示され、操作パネルを閉じると広く見られます。取得はスナップショットです。移動後は再取得してください。
3. 現在地の周辺5kmにある、地震対応の指定緊急避難場所を表示します。地図や一覧から目的地を選び、別の送信同意後にGoogleの通常徒歩経路を表示します。「近くの3候補の徒歩経路を比較」では直線距離で近い最大3地点について道路距離を比較します。全施設を網羅した最短経路の保証ではありません。
4. 「地域の地震」では現在地の対象地域に関係する直近10分の地震情報を表示します。情報が来ると地図上にも表示します。対象地域の情報が届いた後に避難場所を確認・比較できます。自動で避難を指示したり、未同意の経路送信を行ったりしません。
5. 「支援依頼」でGPSを取得して依頼します。「支援協力」では自分のGPSから2km以内で、能力・必要言語が合う本人申請の依頼だけを探せます。正確な相手の位置、相手の経路、相手の利用者IDは返しません。
6. 支援者が承諾すると、両者の2km圏が重なる公開避難場所から合流地点を自動選択します。双方の直線距離の合計を最小にし、その地点への両者の通常徒歩経路が存在し、各移動時間目安が30分以内であることを確認します。災害時の安全性の判定ではありません。有効な地点がない場合は成立させません。
7. 双方がそれぞれGPSを取得し、共通合流地点への自分の道順を表示します。相手のGPSへ直接向かう機能はありません。公開地点は施設代表点であり入口ではないため、現地の入口・立入り可否も確認してください。
8. 実際に相手と会えたことを各自が確認し、新しいGPSで合流地点から100m以内を確認して「合流を確認」を押します。両方の確認後だけ合流済みにできます。GPSは物理的な対面の証明ではありません。支援完了・中止・30分の期限切れで位置と双方のclaimを削除します。中止にはGPS不要です。

## 実データと未確認事項

| ---------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 現在地           | Webは `navigator.geolocation`、ネイティブはCapacitor。高精度要求・15秒タイムアウト・キャッシュ無効 | GPS誤差、屋内、バックグラウンド常駐、実機ごとの差異          |
| 地図・徒歩経路   | Google Maps JavaScript / Routes API                                                                | 道路の被災・階段回避・勾配・幅員・車いすの通行可否           |
| 個人設定         | 保存プロフィールの案内言語、通常1m/s・その他0.7m/sとGoogle時間の遅い方                             | 移動条件に適合する経路を探索したという意味ではない           |
| 避難場所         | 国土地理院 `skhb04` z10 GeoJSON。`disaster4=1` の実在する地震対応指定緊急避難場所                  | 開設、収容可能数、入口、敷地内動線、受入対象、最新の指定状況 |
| 地震             | P2P地震情報API v2 `/history` の551（地震情報）・556（緊急地震速報・警報）                          | 配信遅延・欠落・停止、OSの警報との同等性、背景受信           |
| 合流             | 実GPSによる本人申請・公開合流地点・両者の通常徒歩経路・双方の目視確認                              | 相手の身元、能力の第三者証明、救助サービスとしての運用       |
| ストリートビュー | Google Mapsの公開URLで道順の地点を開く                                                             | 現在の道路状況、カメラAR。過去画像として扱う                 |

指定緊急避難場所と、滞在する指定避難所は別です。国土地理院データは未登録・未公開地域や古い情報を含む場合があります。最新かつ詳細な状況は当該自治体へ確認してください。指定は災害種別ごとで、今回の地震対応を津波や洪水へ流用しません。データは随時更新されます。

## 地震の地域絞り込み

- 震源距離の閾値は使いません。遠い震源でも現在地が警報・震度の対象なら表示します。
- GPSを国土地理院の逆ジオコーダーで市区町村コードに対応づけ、気象庁の「緊急地震速報や震度情報で用いる区域の名称」と国土地理院の自治体定義から作った参照表で地震細分区域を決定します。天気予報の地域区分は流用しません。
- 556は発表された `areas.name` と現在地の地震細分区域を照合します。551はその区域名または区域内自治体の観測点を照合します。県名だけで判定しません。
- 参照表の曖昧・未対応な自治体や逆ジオコーダーで地域を決定できない地点は `area_unknown`。対象なし・取得不能・未判定を区別します。
- 警報のイベント番号・続報番号をまとめ、最新の取消・テスト電文は警報から除外します。同じ情報の重複、10分より古い情報、未来30秒より先の情報も除外します。
- Web表示中は15秒周期です。履歴取得はプロセス共通15秒キャッシュ（551/556の2要求）で、同一プロセスの利用者数に比例して配信元へ要求しません。P2Pの `/history` の制限はIPあたり60要求/分です。マルチインスタンス化前には共有キャッシュか単一受信サービスが必要です。
- 初期・再接続での履歴確認用です。WebSocketの常駐受信、音声・プッシュ通知、オフライン、OSバックグラウンドは未実装です。P2P公式仕様は緊急地震速報としての利用を非推奨とし配信品質を保証していません。したがってアプリは訓練・試験表示を維持します。

参照表は `data/reference/seismic-areas.json`（取得日と出典を同梱）です。更新はMacなら `backend/.venv/bin/python scripts/update_seismic_areas.py`、Windowsなら `backend\.venv\Scripts\python.exe scripts\update_seismic_areas.py`。公式HTMLの行・列構成変更を検出した場合は既存ファイルを置き換えません。差分と未対応自治体をレビューしてコミットしてください。気象庁の元表の公表日は取得日と異なります。

## データの保存と責務

- `services/location.ts`：WebのGPS読取りと権限拒否時の説明。
- `services/realData.ts`：生成API型を使うアプリAPI接続。画面は外部プロバイダーへ直接経路計算を依頼しません。
- `features/useRealEnvironment.ts`：表示中の情報取得。位置をURLや永続キャッシュへ入れません。
- `backend/app/services/local_earthquakes.py`：地域照合・続報・取消・時間窓。
- `real_shelters.py`：公式タイルの境界を含む3×3取得、地震適合・5km絞り込み、最大3件の実道路比較。
- `public_data.py`：固定ホストの読取り、4MB上限、タイムアウト、128件までのタイル・配信キャッシュ。取得失敗を架空データへ置換しません。
- `real_assistance.py`：認証・同意・状態遷移・到着確認。外部通信をFirestoreトランザクションの外で済ませ、承諾時に状態・位置・プロフィール・両者のclaimを再検証します。
- `real_assistance`：参加者IDと状態、公開合流地点。APIは当事者へも相手のIDを返しません。
- `real_private_locations`：依頼者の非公開GPSと30分の期限。`real_assistance_claims`：同時確定の防止。どちらもクライアントから直接読み書きできません。支援者のGPS・両者の経路形状は保存しません。
- 経路計算の2地点はTASUKUに保存しません。別機能の支援依頼で共有へ同意した場合だけ上記の非公開位置を保存します。正確な位置や外部エラー本文をログへ出しません。自動保守に加えて `real_private_locations.expiresAt` のFirestore TTLを設定します。

全件scan・プロセス単位のRoutesレート制限は小規模チーム試験向けです。一般公開の運用拡大前に地域・状態のインデックス、共有レート制限、本人確認と通報・不正利用対策、監査・運用、バックグラウンド通知を追加してください。

## 設定と検証

既存のFirebase/Maps/Routes設定を使用します。`REAL_ROUTES_ENABLED=true` と `ROUTES_PROJECT_ID=tasuku-77c63` をAPIに設定し、Routes APIを有効化、実行アカウントに `roles/serviceusage.serviceUsageConsumer` が必要です。P2PとGSIの公開情報にAPIキーは不要です。外部サービスは停止・遅延することがあります。Googleの実経路利用には課金が発生し得ます。

GPSは端末で試してください。開発者の検証には固定の公開地点を使用し、ユーザーのGPSを代わりに取得しません。テスト内容と実サービス・実機の未確認事項は [TESTING.md](TESTING.md) を参照してください。
